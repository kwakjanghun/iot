🗣 첫 마디 "물감은 섞을수록 탁해지죠. 검정에 가까워집니다. 그런데 빛은 반대예요. 섞을수록 밝아집니다. 다 섞으면 뭐가 될까요?"
🎨 비유 — 손전등 세 개

빨강·초록·파랑 손전등을 같은 벽에 함께 비추면 어떻게 될까요?

그 자리는 더 밝아지고, 결국 하얘집니다.

빛은 겹칠수록 밝아져요. 이걸 가산혼합이라고 합니다.

물감처럼 탁해지는 건 감산혼합 — 정반대입니다.

💡 비유 — LED 하나 안에 전구 세 개

RGB LED 한 칸 안에는 빨강·초록·파랑 전구가 나란히 들어 있습니다.

각 전구의 세기를 0~255로 조절해서 색을 만들어요.

256 × 256 × 256 = 약 1677만 가지 색이 나옵니다.

코드 1단계 — 전체 코드

/*
  ESP32 올인원 키트
  무지개 분위기 조명 (rainbow.ino)
*/
// WS2812 RGB LED 라이브러리 불러오기
#include <NeoPixel_ESP32.h>
#define PIN 15

Adafruit_NeoPixel strip = Adafruit_NeoPixel(6, PIN);  // LED 6개를 15번 핀에

void setup()
{
  strip.begin();        // RGB LED 사용 시작
  strip.show();         // 화면(LED 상태) 갱신
}

void loop()
{
  strip.setPixelColor(0, strip.Color(255, 0, 0));       // 첫 번째 LED는 빨간색
  strip.setPixelColor(1, strip.Color(0, 255, 0));       // 두 번째 LED는 초록색
  strip.setPixelColor(2, strip.Color(0, 0, 255));       // 세 번째 LED는 파란색
  strip.setPixelColor(3, strip.Color(255, 255, 0));     // 네 번째 LED는 노란색
  strip.setPixelColor(4, strip.Color(255, 0, 255));     // 다섯 번째 LED는 보라색
  strip.setPixelColor(5, strip.Color(255, 255, 255));   // 여섯 번째 LED는 흰색
  strip.show();       // 설정한 색으로 LED 갱신
  delay(100);       // 잠깐 기다려 표시를 안정시킴
}

질문 학생이 물어보면

"왜 0번부터 세요? 1번부터 아니고요?"
컴퓨터는 0부터 세는 게 기본이에요. LED 6개면 0·1·2·3·4·5입니다. 실수로 setPixelColor(6, ...)이라고 쓰면 아무 일도 안 일어납니다 — 그런 칸이 없거든요.
"선이 하나뿐인데 어떻게 6개를 따로 조종해요?"
각 LED 안에 작은 제어 칩이 들어 있어요. 첫 번째 LED가 데이터를 받아 맨 앞 24비트만 자기 것으로 가져가고, 나머지는 다음 LED로 넘깁니다. 줄줄이 넘기니까 선 하나로 됩니다.
🧠생각 넓히기 정답은 토글 안에
색을 만들 줄 알게 됐습니다. 그럼 이건?
문제 1
색 섞어보기에서 R·G·B를 전부 255로 올리면 흰색이 됐죠. 그럼 전부 128로 하면 무슨 색일까요? 회색? 아니면 다른 색?
같이 생각해보기
어두운 흰색 — 즉 회색으로 보입니다. 세 색의 비율이 같으면 색기운이 없어져요. 비율이 같은 채로 세기만 낮추면 흰색 → 회색 → 검정으로 갑니다. 👉 색은 비율이 정하고, 밝기는 전체 크기가 정합니다. 그래서 setBrightness로 색은 그대로 두고 밝기만 낮출 수 있어요.
문제 2
LED 6개를 60개로 늘리고 싶습니다. 선은 여전히 한 가닥인데, 무엇이 문제가 될까요?
같이 생각해보기
연결은 됩니다 — 줄줄이 이어 붙이면 되니까요. 문제는 둘입니다. 첫째 시간: 데이터가 60개를 다 지나가야 하니 갱신이 느려집니다. 둘째 전기: LED 60개가 흰색으로 켜지면 전기를 많이 먹어서 보드만으로는 전력이 모자랍니다. 👉 "연결되니까 되겠지"가 아니라 시간과 전기를 같이 따져야 합니다. 실제 제품을 만들 때 꼭 부딪히는 벽이에요.

🌊 색 채우기 — 내가 만드는 명령어

🗣 첫 마디 "6개를 빨강으로 채우려면 setPixelColor를 6번 써야겠죠? 색을 바꿀 때마다 또 6번, 또 6번… 이걸 한 줄로 줄일 수 있다면 어떨까요?"
📼 비유 — 즐겨찾기 버튼

같은 동작을 매번 손으로 하면 귀찮죠.

그래서 버튼 하나에 등록해두고 필요할 때 누릅니다.

코드에서 그 버튼이 함수예요.

여러 줄을 이름 하나로 묶어두고, 그 이름만 부르면 됩니다.

🆕 지금까지와 다른 점

03장에서 쓴 digitalWrite·delay는 남이 만들어 준 함수였습니다.

오늘은 내가 직접 함수를 만듭니다.

이름도 내가 정하고, 인수도 내가 정해요.

코드 1단계 — 전체 코드

/*
  ESP32 올인원 키트
  색 채우기 효과 (colorwipe.ino)
*/
#include <Adafruit_NeoPixel.h>
#define LED_PIN  15   // WS2812를 IO15에 연결
#define LED_NUM  6    // RGB LED 6개
Adafruit_NeoPixel strip(LED_NUM, LED_PIN, NEO_GRB + NEO_KHZ800);

void colorWipe(uint32_t c, uint8_t wait) {   // 한 칸씩 색을 채우는 함수
  for (uint16_t i = 0; i < strip.numPixels(); i++) {
    strip.setPixelColor(i, c);   // i번째 LED를 색 c로
    strip.show();                // 실제 LED에 반영
    delay(wait);
  }
}

void setup() {
  strip.begin();
  strip.setBrightness(50);
  strip.show();
}

void loop() {
  colorWipe(strip.Color(255, 0, 0), 50);  // 빨강으로 차례로 채움
  colorWipe(strip.Color(0, 255, 0), 50);  // 초록
  colorWipe(strip.Color(0, 0, 255), 50);  // 파랑
  colorWipe(strip.Color(0, 0, 0), 50);    // 끄기
}

질문 학생이 물어보면

"uint32_t는 뭐예요? int랑 달라요?"
상자의 크기를 정해둔 것입니다. uint8_t는 작은 상자(0~255), uint32_t는 큰 상자예요. 색은 빨강·초록·파랑 각 8비트 = 24비트라 큰 상자가 필요합니다. u는 "음수 없음(unsigned)"이라는 뜻이고요.
"함수 이름은 아무거나 지어도 돼요?"
거의 그렇습니다. 다만 숫자로 시작하면 안 되고, 띄어쓰기도 안 됩니다. 그리고 하는 일이 드러나는 이름이 좋아요. colorWipe는 "색으로 쓸어낸다"는 뜻이라 딱 맞죠.

문제 1
색을 맨 뒤에서부터 거꾸로 채우고 싶습니다. 함수 안에서 어디를 고쳐야 할까요?
같이 생각해보기
for문의 방향만 뒤집으면 됩니다. i = 0; i < 6; i++ 을 i = 5; i >= 0; i-- 로. 03장 숨쉬는 LED에서 밝아졌다 어두워질 때 쓴 방법과 똑같아요. 👉 함수 안을 한 번만 고치면 이 함수를 부르는 네 곳이 전부 바뀝니다. 이게 함수로 묶어둔 진짜 이유예요.
문제 2
이 함수에 인수를 하나 더 넣어서 "몇 번째 칸부터 채울지"도 정하고 싶습니다. 무엇이 달라져야 할까요?
같이 생각해보기
만드는 줄과 부르는 줄, 둘 다 바꿔야 합니다. 만드는 줄에 uint16_t start를 추가하고, for문의 시작을 i = start로. 그리고 부르는 줄도 값을 세 개 넘겨야 하죠. 👉 함수의 빈칸 개수를 바꾸면 부르는 쪽도 전부 바꿔야 합니다. 그래서 처음 만들 때 "무엇을 빈칸으로 둘지"를 잘 정해야 해요.

💫 빛의 흐름 — 핀 번호도 숫자다

🗣 첫 마디 "이번엔 RGB가 아니라 보통 LED 네 개예요. IO12·13·14·15에 하나씩 달려 있습니다. 이걸 차례로 켜서 빛이 흐르는 것처럼 만들어 봅시다."
🏃 비유 — 파도타기 응원

경기장에서 관중이 차례로 일어섰다 앉으면 파도처럼 보이죠.

한 사람 한 사람은 그냥 일어섰다 앉을 뿐입니다.

LED도 똑같아요. 순서와 타이밍이 흐름을 만듭니다.

🔑 오늘의 핵심 발견

지금까지 핀 번호는 고정된 값이었죠. digitalWrite(5, HIGH)처럼요.

그런데 IO12·13·14·15는 연속된 숫자입니다.

그럼 핀 번호 자리에 변수를 넣으면 어떻게 될까요?

코드 1단계 — 전체 코드

/*
  ESP32 올인원 키트
  빛의 흐름 만들기 (flow_light.ino)
*/
void setup()
{
  for(int i = 12; i <= 15; i++) // IO12~IO15를 한꺼번에 출력 모드로
  {
    pinMode(i, OUTPUT);
  }
}

void loop()
{
  for(int i = 12; i <= 15; i++)  // IO12 → IO15 차례로 켜기
  {
    digitalWrite(i, HIGH);
    delay(200);
    digitalWrite(i, LOW);
  }
  for(int i = 15; i >= 12; i--) // IO15 → IO12 되돌아오기
  {
    digitalWrite(i, HIGH);
    delay(200);
    digitalWrite(i, LOW);
  }
}

i--1씩 줄임 (i++의 반대)
🗣 "두 번째 for문은 방향만 반대예요. 그래서 빛이 되돌아옵니다."
⚠️ 왜 하필 IO12~IO15일까
연속된 번호라서입니다. IO12·26·5처럼 흩어져 있으면 for문으로 못 묶어요. 회로를 설계할 때 연속된 핀에 몰아 두면 코드가 짧아집니다.

"LED를 세 개만 켜려면요?" (교재 연습문제 Q2)

"핀이 연속이 아니면 어떻게 해요?"
배열이라는 걸 씁니다. 핀 번호를 목록으로 적어두고 차례로 꺼내 쓰는 방법이에요. 지금은 몰라도 되지만, "흩어진 핀도 방법이 있다"는 것만 알아두세요.

문제 1
지금은 한 번에 한 칸만 켜집니다. 꼬리가 남는 혜성처럼 만들려면 무엇이 달라져야 할까요?
같이 생각해보기
끄는 시점을 늦추면 됩니다. 지금은 켜자마자 바로 LOW로 끄죠. 앞의 것을 한두 칸 뒤에 끄면 두세 칸이 동시에 켜져 꼬리처럼 보입니다. RGB LED라면 뒤로 갈수록 어둡게 해서 더 자연스럽게 만들 수 있고요. 👉 "언제 켜느냐"만큼 "언제 끄느냐"도 효과를 만듭니다.
문제 2
이 코드에는 delay(200)이 들어 있어서, 빛이 흐르는 1.6초 동안 ESP32는 다른 일을 못 합니다. 만약 그 사이 버튼을 눌렀다면 어떻게 될까요?
같이 생각해보기
못 알아챕니다. delay는 "그 시간 동안 아무것도 하지 말고 기다려라"는 뜻이거든요. 가만히 서서 시계만 보는 상태예요. 👉 이게 delay의 가장 큰 약점입니다. 버튼과 센서를 함께 다루려면 기다리지 않고 시간을 재는 방법이 필요해요. (08장 버튼 입력에서 다시 만납니다)

보너스 극장 조명 효과 — theaterchase.ino

교재에는 없지만 실습코드와 영상이 들어 있는 네 번째 예제입니다. 세 칸마다 하나씩 켜서 흐르는 마퀴 조명을 만듭니다.

▶ 실행 결과 — 극장 간판처럼
세 칸마다 하나씩 · 0.05초마다 한 칸씩 밀림 
void theaterChase(uint32_t c, uint8_t wait) {
  for (int j = 0; j < 10; j++) {            // 같은 동작을 10번 반복
    for (int q = 0; q < 3; q++) {
      for (int i = 0; i < strip.numPixels(); i += 3)
        strip.setPixelColor(i + q, c);      // 세 칸마다 한 LED만 켬
      strip.show();
      delay(wait);
      for (int i = 0; i < strip.numPixels(); i += 3)
        strip.setPixelColor(i + q, 0);      // 다시 끔
    }
  }
}
🔢 for문 세 개가 겹쳐 있습니다

i — 세 칸씩 건너뛰며 (0, 3) 같은 자리를 한꺼번에 칠함

q — 0→1→2로 한 칸씩 밀어서 흐르는 느낌을 만듦

j — 그 패턴을 10번 반복

안쪽부터 읽으면 이해가 쉽습니다. i가 칠하고, q가 밀고, j가 반복.

용어 라이브러리 · 객체 — 새로 나온 말

03장에는 없던 개념이 두 개 나왔습니다.

#include <Adafruit_NeoPixel.h>

라이브러리 불러오기. 남이 만들어 둔 함수 묶음을 가져다 씁니다.
없으면 setPixelColor 같은 걸 직접 다 만들어야 해요

Adafruit_NeoPixel strip(6, 15, ...);

객체 만들기. "LED 6개가 15번 핀에 달린 줄" 하나를 strip이라 이름 붙임

strip.show();

점(.)은 "~의"라는 뜻. "strip 의 show 기능을 써라"

📻 비유 — 라디오 한 대

Adafruit_NeoPixel은 라디오 설계도입니다.

strip은 그 설계도로 만든 진짜 라디오 한 대고요.

strip.show()는 그 라디오의 버튼을 누르는 것입니다.

라디오가 두 대면 각각 이름을 다르게 붙여 따로 조종할 수 있어요.

⚠️ 파일마다 include가 다릅니다
rainbow.ino는 NeoPixel_ESP32.h를, colorwipe.ino와 theaterchase.ino는 Adafruit_NeoPixel.h를 씁니다. 학생 PC에 Adafruit NeoPixel 라이브러리가 설치돼 있어야 뒤의 두 개가 컴파일됩니다. 수업 전에 한 대에서 미리 열어 확인해 두면 좋습니다.

밝기 setBrightness — 색은 그대로, 밝기만

colorwipe.ino에는 있고 rainbow.ino에는 없는 줄입니다.

strip.setBrightness(50);

전체 밝기를 0~255로. 50이면 약 20% 밝기.
색의 비율은 그대로 두고 세기만 낮춥니다

"RGB LED는 정면으로 보면 눈이 아플 만큼 밝습니다. 수업 중엔 50 정도로 낮춰 두는 게 좋아요."
"밝기를 낮추면 색이 변하나요?"
색은 그대로입니다. 세 색의 비율을 유지한 채 전체를 줄이거든요. 빨강(255,0,0)을 반으로 줄이면 (128,0,0) — 어두운 빨강이지 다른 색이 아닙니다. 실습 1의 색 섞어보기에서 세 슬라이더를 같은 비율로 내려보면 확인됩니다.
