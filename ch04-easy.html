BASIC

💡 RGB LED가 뭐길래

알마다 작은 제어 칩이 들어 있어서, 선 한 가닥으로 여섯 알의 색을 따로 정할 수 있습니다.

전구 한 알 안에 전구 세 개

보통 LED는 색이 하나입니다.

빨간 LED는 빨강만 냅니다. 초록 LED는 초록만 냅니다.

RGB LED는 다릅니다. 알 하나 안에 빨강·초록·파랑 LED가 나란히 세 개 들어 있습니다.

세 빛을 서로 다른 세기로 켜면, 한 알에서 온갖 색이 나옵니다.

이 부품의 이름은 WS2812, 별명은 네오픽셀입니다. 키트에는 이 알이 여섯 개 한 줄로 붙어 있습니다.

📮 우편배달부 비유

편지 여섯 통을 한 묶음으로 첫 집에 건넵니다.

첫 집은 맨 위 한 통만 가집니다. 남은 다섯 통은 옆집에 넘깁니다.

옆집도 한 통만 갖고 다시 넘깁니다. 이렇게 여섯 집이 각자 자기 편지를 받습니다.

배달부는 첫 집에만 갔습니다. WS2812도 똑같습니다. 선은 한 가닥인데, 알마다 다른 색을 받습니다.

직접 해보기 · 색 정보가 지나가는 길
 
🔑 24비트 = 8 + 8 + 8
빨강 0~255, 초록 0~255, 파랑 0~255.
한 색당 8비트씩, 세 개를 합쳐 24비트가 알 하나의 몫입니다.
256 × 256 × 256 = 약 1,677만 가지 색.

🎨 물감과 빛은 반대다

물감은 섞을수록 어두워집니다. 빨강 물감에 파랑 물감을 섞으면 탁한 보라가 됩니다. 이걸 감산혼합이라고 합니다.

빛은 반대입니다. 섞을수록 밝아집니다. 이게 가산혼합입니다.

손전등 세 개를 떠올려 봅니다. 빨강 손전등과 초록 손전등을 같은 곳에 비추면 노랑이 됩니다. 세 개를 다 비추면 흰색이 됩니다.

🏫 사물함 비유

교실 뒤 사물함에는 번호가 붙어 있습니다.

"3번 사물함에 빨간 공을 넣어라." 이렇게 말하면 됩니다.

LED 여섯 알도 똑같습니다. 0번부터 5번까지 번호가 있습니다.

단, 컴퓨터는 0부터 셉니다. 여섯 개면 0·1·2·3·4·5입니다. 실수로 6번을 부르면 아무 일도 안 일어납니다. 그런 칸이 없기 때문입니다.

01_rainbow.ino — 전체 코드
/*
  ESP32 올인원 키트
  무지개 분위기 조명
*/
// WS2812 RGB LED 라이브러리 불러오기
#include <NeoPixel_ESP32.h>
#define PIN 15

Adafruit_NeoPixel strip = Adafruit_NeoPixel(6, PIN);  // LED 6개를 15번 핀에 연결한 것으로 설정

void setup()
{
  strip.begin();        // RGB LED 사용 시작
  strip.show(); // 화면(LED 상태) 갱신
}

void loop()
{
  strip.setPixelColor(0, strip.Color(255, 0, 0));       // 첫 번째 LED는 빨간색
  strip.setPixelColor(1, strip.Color(0, 255, 0));       // 두 번째 LED는 초록색
  strip.setPixelColor(2, strip.Color(0, 0, 255));       // 세 번째 LED는 파란색
  strip.setPixelColor(3, strip.Color(255, 255, 0));     // 네 번째 LED는 노란색
  strip.setPixelColor(4, strip.Color(255, 0, 255));     // 다섯 번째 LED는 보라색
  strip.setPixelColor(5, strip.Color(255, 255, 255));   // 여섯 번째 LED는 흰색
  strip.show();       // 설정한 색으로 LED 갱신
  delay(100);         // 잠깐 기다려 표시를 안정시킴
}

이름이 왜 두 번 나올까

같은 Adafruit_NeoPixel 이 한 줄에 두 번 나와서 헷갈리는 자리입니다. 뜻이 다릅니다.

앞의 것은 종류를 밝히는 말, 도면의 이름입니다.

뒤의 것은 도면대로 진짜 물건을 하나 찍어내라는 명령입니다.

int ledPin = 5; 에서는 값이 그냥 5 였습니다. 숫자는 그 자체로 완성이니까요.

그런데 LED 줄은 그냥 만들 수 없습니다. 알이 몇 개인지, 어느 핀에 달렸는지를 알려줘야 만들어집니다. 그래서 괄호에 6 과 PIN 을 넣습니다.

이 줄이 맨 위에 있는 이유

setup() 에서도 쓰고 loop() 에서도 씁니다.

둘 중 한 곳 안에 넣으면 다른 쪽에서 못 씁니다. 03장의 int ledPin = 5; 가 맨 위에 있던 것과 같은 이유입니다.

🔁 같은 챕터에 표기가 두 가지

세 숫자가 하나로 뭉친다

Color 는 세 숫자를 받아서 하나의 숫자로 뭉쳐 돌려줍니다.

그 뭉친 숫자가 그대로 setPixelColor 의 색 자리에 들어갑니다.

8칸안 씀 (W)224 자리
8칸빨강 R216 자리
8칸초록 G28 자리
8칸파랑 B20 자리

한 칸(비트)은 0 아니면 1을 담습니다. 한 색당 8칸이면 0~255 — 04장 내내 나온 그 숫자입니다.

🔑 여기서 "약 1,677만 가지"가 나옵니다
세 색이 8칸씩 = 24칸. 24칸으로 만들 수 있는 가장 큰 수가 16,777,215 입니다. 0부터 세면 16,777,216가지 — 곧 약 1,677만 가지 색입니다. 
Color(255, 0, 0)       → 16711680
Color(255, 255, 255)   → 16777215   // 가장 큰 값
🧩 자료형 이름 뜯어보기
힌트에 뜨는 uint32_t 는 이렇게 나뉩니다. 
uint32_t  =  u(unsigned, 음수 없음) + int(정수) + 32(칸 개수) + _t(type, 자료형)
색에 필요한 건 24칸인데 왜 32칸일까요? 그릇 크기가 8 · 16 · 32 만 있어서 24짜리 그릇이 없기 때문입니다. 남는 8칸은 흰색 전용 알이 따로 달린 제품(RGBW)에서 씁니다. 우리 키트는 RGB라 비워 둡니다.
이름의 뜻 show(보여주다) → "메모해둔 색을 실제 LED에 내보내라"

💡 이 줄이 없으면 LED가 안 켜집니다. setPixelColor는 메모지에 적는 것, show가 실제로 보내는 것입니다.

setup의 show는 무엇을 보낸 걸까

setup에서는 아직 색을 하나도 안 적었습니다. 메모지가 백지입니다.

strip 을 만들 때 라이브러리가 색을 담을 자리를 전부 0으로 채워 두기 때문입니다. 그리고 Color(0, 0, 0) 은 검정, 곧 꺼짐입니다.

그래서 setup의 show() 는 결과적으로 여섯 알을 모두 끕니다. 전원을 켜는 순간 LED가 아무 색으로나 켜져 있을 수 있어서, 깨끗한 상태에서 출발하는 것입니다.

🔑 show는 지우는 명령이 아닙니다
show 가 하는 일은 언제나 하나입니다 — 메모지에 적힌 것을 그대로 내보내기. 
strip.show();   // setup — 메모지: 전부 0        → 다 꺼짐
strip.show();   // loop  — 메모지: 빨초파노보흰  → 무지개
같은 명령입니다. 명령이 달라진 게 아니라 메모지 내용이 달라진 것입니다. 프린터의 인쇄 버튼과 같습니다 — 빈 문서를 인쇄하면 백지가 나오지, 프린터가 무엇을 지운 게 아닙니다.

코드 읽기

#include <NeoPixel_ESP32.h>
남이 만들어 둔 기능 묶음을 가져옵니다. 전처리기 지시자라서 세미콜론이 없습니다.
#define PIN 15
"PIN이라고 쓰면 15로 읽어라" — 숫자에 이름표를 붙입니다.
Adafruit_NeoPixel strip = …
객체를 만듭니다. "IO15에 달린 여섯 알짜리 줄"에 strip이라는 이름을 붙입니다.
strip.begin()
점(.)은 "~의"라는 뜻입니다. strip의 begin 기능 — 이 줄을 쓰기 시작한다고 알립니다.
setPixelColor(0 … 5)
여섯 알에 색을 하나씩 적어 둡니다. 아직 불은 안 들어옵니다.
strip.show()
적어 둔 여섯 색을 한꺼번에 내보냅니다. 이제 불이 켜집니다.
delay(100)
0.1초 쉬고 loop가 처음으로 돌아갑니다. 같은 색을 다시 적으므로 화면은 그대로입니다.
⚠️ 가장 흔한 실수 — show를 빠뜨림
색은 다 정해뒀는데 내보내질 않은 것입니다. LED는 그대로 꺼져 있습니다.
또 하나: 01_rainbow.ino 는 <NeoPixel_ESP32.h> 를, 나머지 셋은 <Adafruit_NeoPixel.h> 를 씁니다. 같은 라이브러리인데 설치본에 따라 파일 이름이 다릅니다. 컴파일이 안 되면 두 이름을 서로 바꿔 봅니다.

실행 결과

왼쪽부터 빨강 → 초록 → 파랑 → 노랑 → 보라 → 흰색, 여섯 알이 동시에 켜집니다.

색이 변하지 않고 계속 그 상태를 유지합니다.

🔆 setBrightness는 없어도 됩니다
rainbow에는 setBrightness 가 없어서 최대 밝기(255)로 켜집니다. 불을 켜는 데 필요한 명령이 아니라 밝기를 낮추는 선택 사항입니다.
교실에서 눈부시면 strip.setBrightness(50); 을 begin() 다음 줄에 넣습니다. 색은 그대로 두고 세 색의 세기를 같은 비율로 깎습니다.
단 setup에서 한 번만 부릅니다. loop 안에서 계속 바꾸면 저장된 색값 자체가 깎여 색이 뭉개집니다.

문제 1
색 섞기에서 R·G·B를 전부 255로 올리면 흰색이 됐습니다. 그럼 전부 128로 하면 무슨 색일까요? 회색? 아니면 다른 색?
같이 생각해보기
어두운 흰색 — 즉 회색으로 보입니다. 세 색의 비율이 같으면 색기운이 없어집니다. 비율은 그대로 두고 세기만 낮추면 흰색 → 회색 → 검정으로 갑니다. 👉 색은 비율이 정하고, 밝기는 전체 크기가 정합니다. 그래서 setBrightness로 색은 그대로 두고 밝기만 낮출 수 있습니다 — 실습 2에서 만납니다.
문제 2
LED 6개를 60개로 늘리고 싶습니다. 선은 여전히 한 가닥인데, 무엇이 문제가 될까요?
같이 생각해보기
연결은 됩니다 — 줄줄이 이어 붙이면 되니까요. 문제는 둘입니다.
첫째 시간: 데이터가 60개를 다 지나가야 해서 갱신이 느려집니다.
둘째 전기: 60개가 흰색으로 켜지면 전기를 많이 먹어 보드만으로는 전력이 모자랍니다. 👉 "연결되니까 되겠지"가 아니라 시간과 전기를 같이 따져야 합니다. 17장 WiFi·IoT에서 전력 이야기가 다시 나옵니다.
문제 3
여섯 알을 하나씩 시간차를 두고 켜고 싶어서 setPixelColor 사이마다 delay(300) 을 넣었습니다. 차례로 켜질까요?
같이 생각해보기
안 켜집니다. 약 2초 동안 아무 일도 없다가 여섯 알이 한꺼번에 켜집니다.

02_colorwipe.ino — 전체 코드
/*
  ESP32 올인원 키트
  색 채우기 효과 (colorWipe)
*/
#include <Adafruit_NeoPixel.h>
#define LED_PIN  15   // WS2812를 IO15에 연결
#define LED_NUM  6    // RGB LED 6개
Adafruit_NeoPixel strip(LED_NUM, LED_PIN, NEO_GRB + NEO_KHZ800);

void colorWipe(uint32_t c, uint8_t wait) {   // 한 칸씩 색을 채우는 함수
  for (uint16_t i = 0; i < strip.numPixels(); i++) {
    strip.setPixelColor(i, c);   // i번째 LED를 색 c로
    strip.show();                // 실제 LED에 반영
    delay(wait);
  }
}

void setup() {
  strip.begin();
  strip.setBrightness(50);
  strip.show();
}

void loop() {
  colorWipe(strip.Color(255, 0, 0), 50);  // 빨강으로 차례로 채움
  colorWipe(strip.Color(0, 255, 0), 50);  // 초록
  colorWipe(strip.Color(0, 0, 255), 50);  // 파랑
  colorWipe(strip.Color(0, 0, 0), 50);    // 끄기
}

🎪 옛날 극장 간판 비유

극장 간판 둘레에는 전구가 촘촘히 박혀 있습니다.

불빛이 빙글빙글 돌아가는 것처럼 보입니다.

그런데 전구는 하나도 움직이지 않습니다.

몇 칸 건너 하나씩만 켜 두고, 그 자리를 한 칸씩 옮길 뿐입니다. 움직이는 건 켜지는 자리입니다.

03_theaterchase.ino — 전체 코드
/*
  ESP32 올인원 키트
  극장 조명 효과 (theaterChase)
*/
#include <Adafruit_NeoPixel.h>
#define LED_PIN  15   // WS2812를 IO15에 연결
#define LED_NUM  6
Adafruit_NeoPixel strip(LED_NUM, LED_PIN, NEO_GRB + NEO_KHZ800);

void theaterChase(uint32_t c, uint8_t wait) {
  for (int j = 0; j < 10; j++) {            // 같은 동작을 10번 반복
    for (int q = 0; q < 3; q++) {
      for (int i = 0; i < strip.numPixels(); i += 3)
        strip.setPixelColor(i + q, c);      // 세 칸마다 한 LED만 켬
      strip.show();
      delay(wait);
      for (int i = 0; i < strip.numPixels(); i += 3)
        strip.setPixelColor(i + q, 0);      // 다시 끔
    }
  }
}

void setup() {
  strip.begin();
  strip.setBrightness(80);
  strip.show();
}

void loop() {
  theaterChase(strip.Color(255, 255, 255), 50);  // 흰색
  theaterChase(strip.Color(255, 0, 0), 50);       // 빨강
  theaterChase(strip.Color(0, 255, 255), 50);     // 청록
}

중괄호가 없습니다

안쪽 for문을 보면 { } 가 없습니다.

for (int i = 0; i < strip.numPixels(); i += 3)
  strip.setPixelColor(i + q, c);      // 중괄호 없음

for문 몸통이 한 줄이면 중괄호를 생략할 수 있습니다. if 와 while 도 같습니다.

04장 안에서 두 방식이 섞여 있는 것도 이 때문입니다. colorwipe의 for문은 세 줄이라 { } 가 있고, 여기는 한 줄이라 없습니다. 규칙이 다른 게 아니라 줄 수가 다른 것입니다.

🚨 두 줄부터는 반드시 중괄호가 필요합니다
중괄호가 없으면 바로 다음 한 줄만 반복됩니다. 두 번째 줄은 반복 밖으로 빠집니다. 
for (int i = 0; i < 6; i++)
  strip.setPixelColor(i, c);    // ← 이것만 6번 반복
  strip.show();                 // ← 반복 밖! 딱 한 번만 실행
들여쓰기가 나란히 맞춰져 있어서 둘 다 반복될 것처럼 보이지만 아닙니다. 컴퓨터는 들여쓰기를 보지 않습니다. 세미콜론까지가 한 줄일 뿐입니다.
에러가 안 나고 결과만 이상해지기 때문에 찾기가 아주 어렵습니다. 처음에는 한 줄이어도 중괄호를 쓰는 습관이 안전합니다.

두 알은 동시에 켜집니다

안쪽 for문이 setPixelColor 를 두 번 부르는데, 0번과 3번 사이에 시간차가 없습니다.

show() 가 for문 밖에 있기 때문입니다. 두 알의 색을 메모지에 적어만 두고, 한 번에 내보냅니다.

🔑 show를 어디에 두느냐로 결과가 갈립니다
// colorwipe — show가 for문 안
for (...) {
  strip.setPixelColor(i, c);
  strip.show();              // 여섯 번 내보냄 → 한 알씩 차례로

// theaterChase — show가 for문 밖

j는 동작이 아니라 재생 시간입니다

너무 짧아서 눈에 안 보입니다. 그래서 여러 번 반복해 보여주는 것이고, 그 횟수가 10입니다.

색 자리에 0만 썼습니다

strip.setPixelColor(i + q, 0);              // theaterChase — 0만
colorWipe(strip.Color(0, 0, 0), 50);   // colorwipe — Color 씀

둘 다 꺼짐이고 결과가 같습니다. Color(0,0,0) 이 만들어내는 값이 결국 0이기 때문입니다.

색 자리에 들어가는 건 숫자 하나입니다. Color() 는 세 숫자를 하나로 뭉쳐 주는 도우미일 뿐이라, 이미 뭉쳐진 숫자를 알면 직접 써도 됩니다.

setPixelColor(0, 16711680) 이라고 써도 빨강으로 켜집니다. 다만 그 숫자를 보고 빨강인 줄 아는 사람이 없어서 평소엔 Color() 를 씁니다. 0만 예외적으로 그냥 씁니다 — 꺼짐이라는 게 한눈에 보이니까요.

🧮 세 숫자가 어떻게 한 숫자로 뭉쳐질까 — 자릿수 이야기 
Color(r, g, b)  =  r × 65536  +  g × 256  +  b
왜 곱하는 값이 다를까요? 십진수의 자릿수와 똑같습니다. 
375  =  3 × 100  +  7 × 10  +  5 × 1
        백의 자리   십의 자리   일의 자리
곱하는 값이 다른 건 자리가 다르다는 표시입니다. 십진수가 10씩 커진다면, 색은 한 자리가 0~255라서 256씩 커집니다. 
b × 2560 = 1        →  b × 20    =  0칸 밀기
g × 2561 = 256      →  g × 28    =  8칸 밀기
r × 2562 = 65536    →  r × 216   = 16칸 밀기
한 색이 8칸씩 차지하니 다음 색은 8칸씩 밀어서 놓는 것입니다.

셋 다 같은 값을 곱하면 어떻게 될까요? 
Color(255, 0, 0) = 255
Color(0, 255, 0) = 255     // 구분이 안 됨!
Color(0, 0, 255) = 255
빨강인지 초록인지 알 수 없게 됩니다. 자리를 나눠야 서로 침범하지 않습니다.

시·분·초와 같은 구조입니다. 
3시간 25분 10초  →  3×3600 + 25×60 + 10 = 12310초
하나의 숫자로 뭉쳐 놓고, 필요할 때 다시 나눠 꺼냅니다.

라이브러리 실제 코드도 그대로입니다. 
return ((uint32_t)r << 16) | ((uint32_t)g << 8) | b;
              16칸 밀기        8칸 밀기      그대로
<< 16 이 곧 × 65536, << 8 이 × 256 입니다. 곱셈 대신 "밀기"로 쓴 것뿐입니다.

🔢 핀 번호도 그냥 숫자다

지금까지 핀 번호는 고정된 값이었습니다. digitalWrite(5, HIGH) 처럼요.

그런데 이 네 개는 IO12 · 13 · 14 · 15, 연속된 숫자입니다.

그러면 핀 번호 자리에 변수 i를 넣을 수 있습니다.

i가 12에서 15로 늘어나면, 켜지는 핀도 따라서 옆으로 옮겨 갑니다.

04_flow_light.ino — 전체 코드
/*
  ESP32 올인원 키트
  빛의 흐름 만들기
*/
void setup()
{
  for(int i = 12;i <= 15 ;i++) // for 문으로 IO12~IO15 핀을 한꺼번에 출력 모드로 설정
  {
    pinMode(i,OUTPUT);
  }
}

void loop()
{
  for(int i = 12; i <= 15; i++)// IO12 → IO15 순서로 LED를 차례차례 켜기
  {
    digitalWrite(i,HIGH);
    delay(200);
    digitalWrite(i,LOW);
  }
  for(int i = 15; i >= 12; i--)// IO15 → IO12 순서로 LED를 차례차례 켜기
  {
    digitalWrite(i,HIGH);
    delay(200);
    digitalWrite(i,LOW);
  }
}

QUIZ

📝 연습 문제

Q1. 무지개 무드등에서 Color(255,0,0) 을 Color(0,0,255) 로 바꾸면 0번 LED는 무슨 색?
파란색으로 켜집니다.
strip.Color(R, G, B) 는 세 색의 세기를 각각 0~255로 정합니다. (255,0,0) 은 빨강만 켠 것이고, (0,0,255) 는 파랑만 켠 것입니다.
Q2. 빛의 흐름에서 IO12~IO14 세 개만 켜려면 for문 조건을 어떻게 고칠까?
i <= 15 를 i <= 14 로 바꿉니다.
for문은 조건식이 참인 동안 반복합니다. i <= 14 면 i가 12 · 13 · 14 세 번만 돌고 멈춥니다.
되돌아오는 for문도 i = 14 로 함께 고쳐야 왕복이 맞습니다.
Q3. 색 채우기에서 strip.show() 를 for문 바깥으로 빼면?
채워지는 과정이 안 보이고 여섯 알이 한꺼번에 켜집니다.
setPixelColor 는 적어 두기만 하고, show 가 실제로 내보냅니다. 여섯 번 다 적은 뒤 한 번만 내보내면 중간 과정이 사라집니다.

⭐ 오늘의 핵심 세 줄

1. 색은 세 숫자 — 빨강·초록·파랑을 0~255로 섞으면 약 1,677만 가지 색이 나온다
2. 적어 두기와 내보내기 — setPixelColor는 메모, show를 불러야 실제로 켜진다
3. 순서가 움직임을 만든다 — 켜는 자리를 한 칸씩 옮기면 빛이 흐르는 것처럼 보인다
