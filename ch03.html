🫁 숨쉬는 LED — 밝기 조절의 비밀

🗣 첫 마디 "LED는 사실 켜기와 끄기, 딱 두 가지밖에 못 해요. 그런데 어떻게 밝기가 서서히 변할까요?"
🌀 비유 — 선풍기 날개

선풍기 날개가 빨리 돌면 하나의 원판처럼 보이죠.

LED도 1초에 1000번 껐다 켜면, 눈에는 깜빡임이 안 보이고

켜져 있던 시간만큼의 평균 밝기로 보입니다.

이 기술의 이름이 PWM이에요. 비유 먼저, 이름은 나중에!

코드 1단계 — 전체 코드부터 보여주기

/*
  ESP32 올인원 키트 — 숨쉬는 LED (breathing_led.ino)
*/
#define PIN_LED   5      // LED가 연결된 핀 (IO5)
#define CHN       0      // 사용할 PWM 채널 번호
#define FRQ       1000   // PWM 주파수 (1초에 1000번 깜빡)
#define PWM_BIT   8      // 밝기 단계 정밀도 (8비트 = 0~255단계)

void setup()
{
  ledcSetup(CHN, FRQ, PWM_BIT); // PWM 채널 준비
  ledcAttachPin(PIN_LED, CHN);  // LED 핀을 PWM 채널에 연결
}

void loop()
{
  for (int i = 0; i < 255; i++) // 0 → 255 : 점점 밝아짐
  {
    ledcWrite(CHN, i);          // i 만큼의 밝기로 켜기
    delay(10);                  // 10밀리초 기다림
  }
  for (int i = 255; i > -1; i--) // 255 → 0 : 점점 어두워짐
  {
    ledcWrite(CHN, i);
    delay(10);
  }
}

문제 1
지금은 1초에 1000번 깜빡여서 우리 눈에 깜빡임이 안 보였죠. 그럼 FRQ를 5로 바꿔서 1초에 5번만 깜빡이게 하면 LED는 어떻게 보일까요?
같이 생각해보기
깜빡임이 그대로 보입니다. 밝기 조절이 아니라 그냥 껌뻑이는 등이 되죠. 선풍기를 아주 느리게 돌리면 날개가 하나하나 보이는 것과 같습니다. PWM이 밝기로 보이려면 "눈이 못 따라갈 만큼 빨라야" 한다는 게 핵심이에요. 👉 사람 눈은 보통 초당 60번이 넘어가면 깜빡임을 못 느낍니다. 그래서 1000번은 넉넉히 빠른 값이에요.
문제 2
슬라이더를 128에 놓아 보세요. 255의 딱 절반입니다. 그런데 눈으로 볼 때도 절반 밝기로 보이나요?
같이 생각해보기
아니요. 절반보다 훨씬 밝게 느껴집니다. 사람 눈은 어두울 때는 작은 변화도 크게 느끼고, 밝을 때는 큰 변화도 조금만 느낍니다. 그래서 0→50 구간의 변화가 200→255 구간보다 훨씬 크게 보이죠. 숨쉬는 LED가 끝부분에서 "천천히 꺼지는 느낌"이 드는 것도 이 때문입니다. 👉 숫자(기계의 세계)와 느낌(사람의 세계)은 같지 않습니다. 좋은 제품을 만들려면 이 차이를 알아야 해요.

🆘 SOS — 깜빡임의 길이가 곧 언어

🗣 첫 마디 "무인도에 갇혔는데 손전등 하나만 있어요. 말도 글자도 없이, 빛만으로 '살려주세요'를 어떻게 보낼까요?"
📡 비유 — 모스 부호는 깜빡임 언어

S = 짧게 3번 (· · ·)    O = 길게 3번 (— — —)

그래서 SOS = 짧게 3번 → 길게 3번 → 짧게 3번

같은 LED인데 켜져 있는 시간의 길이만 다르게 하면 정보가 됩니다.

코드 1단계 — 전체 코드부터 보여주기

"코드가 길어 보이지만, 사실 같은 덩어리가 3번 나올 뿐이에요. 숫자만 다릅니다."
/*
  ESP32 올인원 키트 — SOS 구조 신호 (sos.ino)
*/
int ledPin = 5;   // LED가 연결된 핀 (IO5)

void setup()
{
  pinMode(ledPin, OUTPUT); // LED 핀을 출력으로 설정
}

void loop()
{
  for (int x = 0; x < 3; x++)  // 빠르게 3번 깜빡 = 'S'
  {
    digitalWrite(ledPin, HIGH); // LED 켜기
    delay(150);                 // 0.15초 유지 (짧게 = 점)
    digitalWrite(ledPin, LOW);  // LED 끄기
    delay(100);
  }
  delay(200); // 글자 사이 간격

  for (int x = 0; x < 3; x++)  // 천천히 3번 깜빡 = 'O'
  {
    digitalWrite(ledPin, HIGH);
    delay(400);                 // 0.4초 유지 (길게 = 선)
    digitalWrite(ledPin, LOW);
    delay(200);
  }
  delay(100);

  for (int x = 0; x < 3; x++)  // 다시 빠르게 3번 = 'S'
  {
    digitalWrite(ledPin, HIGH);
    delay(150);
    digitalWrite(ledPin, LOW);
    delay(100);
  }
  delay(5000); // 5초 쉬고 SOS 반복
}

문제 1
빛 대신 소리로 SOS를 보내고 싶습니다. LED 자리에 부저(스피커)를 꽂는다면, 코드에서 무엇을 바꿔야 할까요?
같이 생각해보기
거의 안 바꿔도 됩니다. 부저를 꽂은 핀 번호만 바꾸면 끝이에요. digitalWrite(HIGH)는 "전기를 보내라"는 뜻이고, LED는 그걸 빛으로, 부저는 소리로 바꿔줄 뿐입니다. 👉 같은 명령이 부품에 따라 다른 결과를 냅니다. 이게 사물인터넷의 기본 원리예요. (05장 소리에서 다시 만납니다)
문제 2
SOS는 왜 하필 · · · — — — · · · 일까요? 더 멋진 모양으로 정할 수도 있었을 텐데요.
같이 생각해보기
가장 단순하고, 헷갈릴 일이 없기 때문입니다. 급할 때 떨리는 손으로도 보낼 수 있어야 하고, 멀리서 흐릿하게 봐도 짧은 것 3번 · 긴 것 3번은 구분이 됩니다. 👉 위급 상황에서 쓰는 신호는 멋짐보다 확실함이 먼저입니다. 여러분이 만들 장치의 경고음도 마찬가지예요.

🚦 신호등 — 순서가 곧 프로그램

🗣 첫 마디 "이번엔 LED가 3개예요. 진짜 신호등처럼 초록 → 노랑 깜빡 → 빨강, 순서대로 켜 봅시다."
📖 비유 — 코드는 요리 레시피

레시피는 위에서 아래로 순서대로 따라 하죠.

코드도 똑같아요. 초록 줄 → 노랑 줄 → 빨강 줄 순서로 쓰면

신호등도 그 순서로 바뀝니다. 그리고 loop()는 끝나면 처음부터 다시.

코드 1단계 — 전체 코드부터 보여주기

"명령어는 아까 SOS와 완전히 똑같아요. 핀이 3개로 늘었을 뿐입니다."
/*
  ESP32 올인원 키트 — 신호등 (traffic_light.ino)
*/
int greenPin  = 27;  // 초록 LED 핀 (IO27)
int yellowPin = 26;  // 노랑 LED 핀 (IO26)
int redPin    = 25;  // 빨강 LED 핀 (IO25)

void setup()
{
  pinMode(greenPin, OUTPUT);  // 세 LED를 모두 출력으로 설정
  pinMode(yellowPin, OUTPUT);
  pinMode(redPin, OUTPUT);
}

void loop()
{
  digitalWrite(greenPin, HIGH); // 🟢 초록불 켜기
  delay(5000);                  // 5초 유지
  digitalWrite(greenPin, LOW);  // 초록불 끄기

  for (int i = 1; i <= 3; i++)  // 🟡 노랑불 3번 깜빡
  {
    digitalWrite(yellowPin, HIGH);
    delay(500);                    // 0.5초
    digitalWrite(yellowPin, LOW);
    delay(500);
  }

  digitalWrite(redPin, HIGH); // 🔴 빨강불 켜기
  delay(5000);                // 5초 유지
  digitalWrite(redPin, LOW);  // 빨강불 끄기
}

이름표 #define과 변수, 뭐가 다른가

03장 안에 두 방식이 다 나옵니다. 숨쉬는 LED는 #define, SOS와 신호등은 int를 씁니다. 둘 다 맞습니다.

#define PIN_LED 5

컴파일 전에 글자를 그대로 갈아끼움. 등호 없음 · 세미콜론 없음 · 메모리 안 씀

int PIN_LED = 5;

진짜 상자를 만들어 5를 담음. 자료형 있음 · 세미콜론 있음 · 도중에 값 변경 가능

const int PIN_LED = 5;

자물쇠를 채운 상자. 읽기만 되고 못 바꿈 → 실수하면 컴파일러가 잡아줌

🔒 비유 — const는 안전벨트

변수는 화이트보드, const는 거기에 코팅을 씌운 것입니다.

"const를 빼면 어떻게 돼요?"
아무 일도 안 일어납니다. 똑같이 잘 작동해요. 딱 하나, 실수로 PIN_LED = 7;이라고 써도 에러 없이 통과합니다. 그러면 LED는 안 켜지는데 에러 메시지가 없어서, 회로를 의심하며 한참 헤매게 되죠. const는 있으면 좋은 안전장치이지, 필수품이 아닙니다.

용어 함수 · 예약어 · 지시자 — 셋은 다릅니다

학생들은 전부 "명령어"라고 부르지만, 정확히는 세 종류입니다.

ledcSetup( ... ) ← 함수

괄호 안에 인수를 받습니다. 자동 완성 목록의 🟣 육각형 표시가 함수라는 뜻.
digitalWrite · pinMode · delay 도 모두 함수

for ( ... ) ← 예약어

C++이 정해둔 단어. 괄호가 있어도 인수가 아니라 초기식·조건식·증감식이라 세미콜론으로 나눕니다.
if · int · void 도 예약어

#define PIN_LED 5 ← 전처리기 지시자

#으로 시작. 컴파일 전에 글자를 바꿔치기합니다. 세미콜론 없음

"셋 다 '명령어'라고 불러도 수업엔 지장 없어요. 다만 괄호 안에 들어가는 걸 전부 '인수'라고 부르면 나중에 헷갈립니다."

위치 #define을 setup 안에 넣어도 되나?

🗣 학생이 물어보면 "넣어도 됩니다. 그런데 결과가 좀 이상해요. 왜 그런지 봅시다."
void setup()
{
  #define PIN_LED 5        // setup 안에서 정의
  pinMode(PIN_LED, OUTPUT);
}

void loop()
{
  digitalWrite(PIN_LED, HIGH);   // ✅ 여기서도 잘 됩니다!
}

#define은 중괄호 { }를 아예 모릅니다.

컴파일 전에 그 줄 아래로 전부 글자를 바꿔버려요.

그래서 setup 안에 적어도 loop까지 바뀝니다.

맨 위에 적는 이유는 빠짐없이 바뀌게 하려고입니다.

⚠️ 딱 하나 규칙 — 순서
전처리기는 위에서 아래로 훑습니다. 정의보다 위에서 쓰면 에러입니다. loop에서 정의하고 setup에서 쓰면 was not declared 오류가 납니다.
#define PIN_LED 5 (setup 안)

loop에서도 쓸 수 있음 — 글자 바꿔치기라 중괄호를 무시

int pinLed = 5; (setup 안)

loop에서 못 씀 — setup이 끝나면 상자가 사라짐 (지역 변수)

"그럼 변수는 왜 사라져요?"
변수는 중괄호 안에서 태어나 중괄호가 닫히면 죽습니다. setup이 끝나는 순간 pinLed라는 상자는 치워지죠. 그래서 setup·loop 양쪽에서 쓸 값은 맨 위(중괄호 바깥)에 선언합니다. 03장 코드들이 전부 그렇게 돼 있어요.

실험 LED 2개를 한꺼번에 숨쉬게 하기

"핀 번호를 도중에 바꾸면 어떻게 될까요? 한번 해봅시다."
int PIN_LED = 5;      // const 없는 변수 (도중에 바꿀 거니까)

void setup()
{
  ledcSetup(CHN, FRQ, PWM_BIT);

  ledcAttachPin(PIN_LED, CHN);   // ① 5번 핀을 붙임

  PIN_LED = 18;                   // ② 이름표 값을 18로 바꿈

  ledcAttachPin(PIN_LED, CHN);   // ③ 18번 핀도 붙임
}                                 // → LED 2개가 똑같이 숨쉼!
⚠️ 핀 고를 때 주의
ESP32는 GPIO 6 · 7 · 8 · 9 · 10 · 11이 내부 플래시 메모리에 연결돼 있습니다. 이 핀을 쓰면 보드가 재부팅을 반복합니다. IO18처럼 여유 있는 핀을 쓰세요. (PWM 금지 핀 34 · 35 · 36 · 39와는 다른 문제입니다)

"두 LED를 따로따로 조종하려면요?"
조절기(채널)를 2개 만들면 됩니다. ledcSetup(0,...)과 ledcSetup(1,...)로 두 개를 만들고, 핀을 하나씩 붙인 뒤 ledcWrite(0, i) · ledcWrite(1, 255 - i)로 쓰면 한쪽이 밝아질 때 다른 쪽은 어두워지는 시소 효과가 납니다.
